# Proposed learning path — outline v0.1

This is a proposed table of contents, not a claim that coverage or literature review is complete.

## Part I — Understand
1. Why agents need memory: everyday examples and terminology
2. Context windows, state, knowledge, retrieval, and memory: boundaries and overlaps
3. Scientific foundations: cognitive analogies and their limits, information retrieval, databases, learning and systems
4. A critical taxonomy: short/long horizons; episodic/semantic/procedural; explicit/implicit; working and persistent; user/task/environment/shared memory

## Part II — Design
5. Memory lifecycle: write, select, index, consolidate, update, forget, delete
6. Representations: text, structured records, embeddings, graphs and hybrid approaches
7. Retrieval and selection: relevance, freshness, provenance, policies and budgets
8. Multi-agent memory: private, shared, role-based and coordinated memories
9. Trust boundaries: privacy, poisoning, prompt injection, user consent, governance and deletion

## Part III — Build
10. Minimal memory-free versus memory-enabled agents
11. Framework and product landscape (versioned and vendor-neutral)
12. Architectures: application state, stores, queues, knowledge systems, vector and graph patterns
13. Example progression: local simple store -> searchable memory -> long-running agent -> multi-agent system
14. Operations: observability, consistency, migration, scalability, cost and reliability

## Part IV — Test and Research
15. Evaluation definitions, workloads, baselines and metrics
16. Failures: incorrect recall, stale beliefs, contradictions, leaks, forgetting errors and retrieval regressions
17. Reproducible experiments and benchmark interpretation
18. Open research questions, trends and future directions

## Standard chapter components

* What the learner will know
* A plain-English analogy and its limitations
* Precise vocabulary and scientific background
* Visual explanation and fully described alternative
* Mechanism, examples, and runnable lab where appropriate
* Trade-offs, limitations and failure modes
* Primary evidence with section/page pointers and official product docs with version/date
* Questions, exercises, answers or hints, and a short glossary

Do not equate biological memory categories with software implementations without qualification. Technologies are examples, not endorsements. All chapter titles and sequence are revisable after the evidence map and reader pilot.
